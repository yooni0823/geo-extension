# ui-panel-spec.md

## 1. Purpose

This document defines the UI structure for the **GEO / AEO Inspector side panel**.

The side panel is the primary interface where developers can:

- view extracted page metadata
- review detected issues
- see recommended schema types
- inspect existing JSON-LD
- generate JSON-LD drafts
- copy structured data

The UI should be **developer-focused, minimal, and easy to scan**.

---

# 2. UI Principles

The UI should follow these design principles:

### 2.1 Developer-first interface

- prioritize clarity over visual design
- display raw values clearly
- allow easy copying of generated schemas

### 2.2 Minimal UI

Avoid heavy styling or complex UI frameworks.

Preferred style:

- simple layout
- lightweight components
- readable code blocks

### 2.3 Structured sections

Group related information into clear sections.

---

# 3. Layout Structure

The side panel should contain **four main sections**.

```
Side Panel
│
├─ Page Overview
│
├─ Issues
│
├─ Schema Recommendations
│
└─ Generated JSON-LD
```

Each section should be vertically stacked.

---

# 4. Section Specifications

## 4.1 Page Overview

Displays extracted page information.

Fields to display:

- URL
- Title
- Meta description
- Canonical URL
- Language
- Open Graph title
- Open Graph description
- Open Graph image
- H1 headings
- H2 headings
- Existing JSON-LD count

Example UI:

```
Page Overview

URL
https://example.com/page

Title
Example Page

Description
Example description text

H1
- Example Page

H2
- Section One
- Section Two

Existing JSON-LD
0 detected
```

---

## 4.2 Issues

Displays warnings generated by the validator.

Each issue should show:

- severity
- message

Example:

```
Issues

⚠ Meta description is missing

⚠ No JSON-LD structured data was found

⚠ Multiple H1 elements detected
```

Severity indicators:

| Severity | UI |
|--------|--------|
| info | grey text |
| warning | yellow icon |
| error | red icon |

---

## 4.3 Schema Recommendations

Displays suggested schema types based on detection rules.

Examples:

```
Schema Recommendations

WebPage
Recommended for general page structure

BreadcrumbList
Breadcrumb navigation detected

Article
Article-like content detected
```

Rules:

- recommendations should include a short reason
- recommendations are suggestions only
- do not auto-generate complex schemas

---

## 4.4 Generated JSON-LD

Displays the generated schema draft.

Conditions:

### Case 1 — No JSON-LD exists

Generate a **WebPage schema draft**.

Display formatted JSON.

Example:

```json
{
  "@context": "https://schema.org",
  "@type": "WebPage",
  "@id": "https://example.com/page#webpage",
  "url": "https://example.com/page",
  "name": "Example Page",
  "description": "Example description",
  "inLanguage": "ko-KR"
}
```

Include:

- **Copy button**
- optional **Download button**

---

### Case 2 — JSON-LD already exists

Display message:

```
Existing JSON-LD detected on this page.
```

Also show the number of schemas detected.

Example:

```
2 JSON-LD blocks detected.
```

Optional:

Display parsed schema types.

Example:

```
Detected schema types:
- WebPage
- BreadcrumbList
```

```
PageOverviewSection.tsx
IssuesSection.tsx

GeneratedSchemaSection.tsx
CodeBlock.tsx
CopyButton.tsx
```

---

# 7. Data Flow

Data flow should follow this order:

```
Content Script
    ↓
Page Extraction
    ↓
Background / Messaging
    ↓
Side Panel React UI
```

Steps:

1. content script extracts page data
2. data is sent via `chrome.runtime.sendMessage`
3. side panel receives the data
4. validators run
5. schema generator runs
6. UI updates

---

# 8. UI State

The side panel should maintain simple application state.

Suggested state structure:

```ts
type PanelState = {
  pageData?: PageAnalysisResult;
  issues: Issue[];
  recommendedSchemas: string[];
  generatedSchema?: object;
};
```

State can be managed using:

- React state
- Zustand (optional)

---

# 9. Code Block Component

JSON-LD should be displayed using a reusable component.

Example component:

```
CodeBlock
```

Responsibilities:

- show formatted JSON
- allow copying
- preserve indentation
- scroll if content is large

---

# 10. Copy Button Behavior

The **Copy button** should:

- copy JSON-LD to clipboard
- show a short success message

Example:

```
Copied JSON-LD to clipboard
```

Implementation:

```
navigator.clipboard.writeText(...)
```

---

# 11. Empty States

Handle empty states gracefully.

Examples:

### No issues

```
No issues detected.
```

### No recommendations

```
No schema recommendations available.
```

### No generated schema

```
Schema generation not required.
```
